# Case Study — Linked Helper Personalization Suite

## Context

This project began as a product/digital marketing test assignment for a B2B SaaS product. The task was not to code a website. The original deliverables were strategy, landing-page content, SEO, and a visual brief for a static Hero illustration.

I later turned the completed assignment into this working front-end concept to show the full path from analysis to implementation.

> This is an independent portfolio concept, not an official Linked Helper production page.

## The brief

The assignment centered on Linked Helper’s Personalization Suite and required a structured landing-page solution grounded in:

- search intent and semantic research;
- competitor analysis;
- Voice of Customer;
- product-value mapping;
- message hierarchy;
- landing architecture;
- final English landing copy;
- SEO metadata;
- a separate Hero-illustration brief.

The challenge was not simply to say that the product uses AI. The market already contains many AI-personalization claims, so the page needed a more defensible positioning angle.

## Research and strategic direction

The analysis led to a central positioning idea:

**Personalization at scale + control over what gets sent.**

The page therefore combines two personalization modes instead of treating them as competing approaches:

1. **AI Personalized Messages** for prospect-specific sequences built from selected context.
2. **Controlled templates** using profile variables, Custom Variables from CSV, Spintax, Message Variations, and presence-based IF–THEN–ELSE fallbacks.

The control layer is part of the value proposition, not a footnote: AI Drafts can be reviewed and edited before approval, and reply detection prevents irrelevant automated follow-ups after a prospect responds.

## Information architecture

The final landing architecture contains 16 blocks:

1. Hero
2. Social Proof Bar
3. Problem / Solution
4. AI Personalization
5. Rule-Based Personalization
6. Review & Reply Control
7. How It Works
8. Use Cases
9. Deep Social Proof
10. Operational Guardrails
11. Support
12. Related Features
13. Pricing
14. Educational Content
15. FAQ
16. Final CTA

This order moves from positioning and trust to product mechanics, use cases, proof, supporting ecosystem, commercial information, objections, and a final conversion action.

## Hero visual concept

The Hero illustration was designed around one readable product flow:

`Prospect Context → Personalized Sequence → Review / Approve`

The central visual element is the prospect-specific message sequence. Context appears on the left, and the review/approval state appears on the right. A smaller secondary layer shows the rule-based template mode with a CSV Custom Variable and IF–THEN–ELSE fallback.

The goal is to communicate the product in a few seconds without relying on abstract AI imagery.

## What I implemented

After the marketing deliverables were complete, I converted the concept into a responsive static front end.

### Front-end work

- semantic HTML structure;
- responsive desktop, tablet, and mobile layouts;
- product-led UI mockups built in HTML/CSS;
- mobile navigation;
- interactive Local / Cloud pricing switch;
- FAQ accordion using native HTML details/summary;
- reduced-motion support;
- SEO title and meta description;
- clear portfolio/disclaimer layer;
- external links routed to official Linked Helper pages rather than fake product actions.

### QA principles

- one H1 and a clear H2 hierarchy;
- primary SEO phrase preserved in the Hero and metadata;
- no invented conversion or reply-rate metrics;
- no absolute safety claims;
- no autonomous AI-send behavior shown;
- IF–THEN–ELSE represented only as presence-based fallback logic;
- pricing and key product facts re-checked against current official Linked Helper pages before the refinement pass.

## AI-assisted workflow

AI was used as a production tool throughout the project: for research organization, comparison, drafting, code generation, and repeated QA passes. The workflow was not based on accepting first-pass output. Each stage was checked against the brief, product evidence, and the previous approved stage before moving forward.

That process is part of the case: the project demonstrates how AI can compress research and implementation time while still requiring human control over scope, evidence, consistency, and final quality.

## Outcome

The original test assignment now exists in three layers:

- **strategy and research** — why the page says what it says;
- **content and visual specification** — what the page should communicate and how the Hero should work;
- **working front-end concept** — a tangible implementation that can be opened, reviewed, and deployed.

The next project stage is live deployment and final visual QA, followed by integration into the main portfolio.
